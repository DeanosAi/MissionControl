## Mission Control VPS definition workshop

### Product direction agreed
The new VPS Mission Control will be a separate app from the existing local Mission Control.

It is defined as a private, self-hosted builder operating system for Dean that will act as a dashboard-driven hub for:
- ideas
- suggested ideas
- projects
- AI builds
- tools
- systems
- automations
- memory/journal
- future modules such as content workflows

### Design direction agreed
The visual direction should be:
- professional modern SaaS as the base
- with a sleek dark control-room feel
- with a subtle cyber edge
- visually appealing and user-friendly
- presentable to other people without being over-polished or flashy

### Functional requirements added
- Ideas should include a Suggested Ideas section for future agent-driven idea discovery.
- AI Builds should show which AI/model is working on each job.
- A Memory / Journal section should record what the app has done and is doing.
- Content should exist as a Coming Soon section for now.
- The system must remain fluid so sections can be changed, added, or removed later without painful rewrites.

- If rate limits or spend pressure require a pause, the user must be told first.

## Backup direction agreed
Backup design for the VPS version should be:
1. Nightly compressed backup created on the VPS first.
2. Local rolling retention kept on the VPS.
3. Secondary copy synced to Dean's local machine when available.
4. If the local machine is offline, the sync should fail gracefully without affecting the running app.
